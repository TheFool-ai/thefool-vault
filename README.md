## 日记与周记

- 日记放 `10-Journal/Daily/YYYY-MM-DD.md`；周记放 `10-Journal/Weekly/YYYY-Www.md`。日期按北京时间，周记用 ISO 周，周一到周日。
- 日记先写二级标题“今日进展”，下设三级标题“完成了什么、达成的共识、待办”；随后单独写二级标题“想法与决定”，最后按需写“阅读与输入”。周记对应“本周进展”。无内容的部分可省略，不补空白日期。
- 按事项合并，写产物、解决的问题和明确决定。区分个人成果、团队产出与进行中；回复消息、参会和确认时间不单独算成果，不逐条抄聊天。
- 个人知识库自身的搭建、目录调整、笔记整理、日记规则和自动化配置，不写入日记或周记。相关约定留在本库说明和个人画像中。
- 待办只收明确需推进或尚未闭环的事项，写下一步；负责人、期限、阻碍有依据再补，普通提问和通知不自动变成待办。
- “想法与决定”保留我明确表达或确认的理解、疑问、收获和个人决定，可以尚未定型；“达成的共识”记录已经对齐的共同结论，不替我编造心得。
- 飞书阅读按主题合并，留标题、链接和主题。只有打开记录时记为浏览，不算已读完或已认同；文档观点与我的判断分开。
- 按事件日期增量更新日记和对应周记，保留来源链接，详细过程留在项目页。跟 AI 说“今天做了什么”或“整理这周”即可。

## 模板与 Obsidian

直接用 Obsidian 打开本目录，模板插件的文件夹设为 `90-Templates`。模板可选，不用填满。

| 模板 | 用于 |
| --- | --- |
| [通用元数据](90-Templates/通用元数据模板.md) | 只加 frontmatter |
| [知识笔记](90-Templates/知识笔记模板.md) | 理解、经验、方法 |
| [项目](90-Templates/项目模板.md) | 项目目标与进展 |
| [需求](90-Templates/需求模板.md) | 知识编译默认按 `需求/迭代/需求名.md` 归档 |
| [日记](90-Templates/日记模板.md) | 当天进展与个人思考 |
| [周记](90-Templates/每周回顾模板.md) | 一周回顾 |

- 模板元数据至少包含 `created`、`updated`、`type`；`created` 记笔记实际建档日期，不随补录更改；`updated` 记最后一次实质修改日期。
- 事件日期与笔记维护日期分开：日记归属、问题来源和时间线按实际发生日期；晚到的信息补到事件当天，元数据不统一减一天。
- 文件名就是标题，模板不带一级标题。
- 需求的 `requirement_created` 写 Meego 原始创建日期，`created` 写本库实际建档日期。
